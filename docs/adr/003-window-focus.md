# ADR-003: 履歴ウィンドウの前面化と元のアプリへのフォーカス復帰の方式

**日付:** 2026-10-17
**ステータス:** 検討中(フェーズ1のスパイクで確定する)

## 背景
グローバルショートカットで履歴ウィンドウを他のアプリの前面に出し、選択後はウィンドウを閉じて直前のアプリにフォーカスを戻し、自動で貼り付ける(US-003・US-004)。トレイ常駐のため、macOS では Dock にアイコンを出したくない。Tauri 公式にはこの用途の専用 API が無く、通常ウィンドウでは難しいという議論がある(tech-research.md 参照)。

## 決定(暫定)
- まず通常の Tauri ウィンドウ(枠なし・最前面・タスクバー非表示・420px 固定幅)で実装する。
- macOS: 起動時にアクティベーションポリシーを Accessory にして Dock に出さない。閉じるときはウィンドウを隠したうえでアプリ自体を隠し(NSApp の hide 相当)、直前のアプリにフォーカスが戻ることを狙う。
- Windows: 表示前に最前面のウィンドウを記録し、閉じた後にそのウィンドウを前面に戻す。
- フェーズ1の最初にスパイクで検証し、macOS で要件を満たせない場合は tauri-nspanel(git の `v2.1` ブランチ)による NSPanel に切り替える。切り替える場合は git 依存の追加になるため、ユーザーに確認してから行う。
- スパイクの結果(採用方式・必要な crate・貼り付け前の待ち時間)は、このファイルのステータスを「決定済み」に更新して記録する。

## 理由
- 依存を増やさず、Tauri 公式の範囲で実現できればそれが最も保守しやすい。
- tauri-nspanel は crates.io 公開版ではなく git ブランチ参照で、単独メンテナのため、必要性を確認してから導入する。

## 却下した代替案
- 最初から tauri-nspanel を使う: 必要かどうかが未確認のまま、git 依存と単独メンテナへの依存を増やす。
- フォーカスを戻さず再コピーだけにする: 要件(自動ペースト)を満たさない。

## 影響
- Accessory 状態では window イベントが届かない、`set_focus()` で Dock に現れる、などの報告がある(未検証)。スパイクで確認する。
- Tauri アプリは起動時に他アプリのフォーカスを奪う(issue #15017、未解決)。起動時(ログイン時)の一瞬に限られるため許容する。
- Windows の `SetForegroundWindow` の制約は一次情報で未確認。スパイクで確認する。
